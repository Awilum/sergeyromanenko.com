02 · How it started

It started with one SQL course.

In 2023, I joined Stepik as an independent course author and published my first course, SQL Introduction , in English. It was an opportunity to turn my professional experience with databases and software development into a structured learning experience — a clear, practical introduction to relational databases and SQL, combining explanations with exercises and knowledge verification.

I gradually expanded the project, developing new courses, refining existing materials and experimenting with different ways of teaching programming through practical assignments. The first publication became the starting point for a catalog that now spans JavaScript, SQL, Python, Java, C#, Go, Kotlin, PHP and Markdown — from complete beginner courses to programming trainers and career programs.

08 · Teaching philosophy

Understanding a concept is only the beginning. Being able to use it is what matters.

My approach to online education is based on the idea that programming skills develop through repeated practice. Understanding an explanation is important, but it is not enough. Students need opportunities to write code, make mistakes, investigate why a solution does not work, and solve new problems independently.

That is why practical assignments form the foundation of my courses. Theory provides the necessary context, while exercises give students the opportunity to turn knowledge into working skills.

  1. 01

    Structured explanations

    Every concept gets a short, focused explanation with examples. Theory provides the context the exercises need.

  2. 02

    Real programming exercises

    Each topic ends in code that has to be written, not just read about. Understanding an explanation is the beginning, not the goal.

  3. 03

    Automatic verification

    Interactive questions and programming tasks are checked automatically, so a wrong answer surfaces immediately, not weeks later.

  4. 04

    Progressive difficulty

    Tasks move from simple to demanding, so students build confidence before they are asked to solve something non-trivial.

  5. 05

    Repetition and consolidation

    Concepts return in new contexts until they hold — the same idea revisited in harder exercises and different problems.

  6. 06

    Independent problem-solving

    The upper layers of the catalog deliberately resemble technical interviews and programming olympiads, where nobody explains the problem first.

09 · The 2026 approach

Stepik CLI

A local-first developer workspace for building and managing Stepik courses.

In 2026, I developed my own structured approach to working with Stepik courses: a software-engineering workflow for creating, maintaining, validating and publishing educational content. The main idea is that a course should be treated as a software project, not as a collection of content maintained exclusively inside a web editor.

  1. 01

    Markdown-first authoring

    Text content for course steps lives in ordinary Markdown files.

  2. 02

    Structured YAML metadata

    Course, section and lesson metadata are explicit, readable YAML.

  3. 03

    Deterministic structure

    Sections, lessons and steps have a predictable directory and file layout — the hierarchy is the filesystem.

  4. 04

    Git-friendly workflow

    Course materials live in a normal Git repository; changes are reviewed like software changes.

  5. 05

    Official API integration

    The CLI communicates with Stepik through the official REST API with OAuth authentication.

  6. 06

    Explicit publishing

    Download from Stepik, edit locally, validate, then deploy explicitly. The local project is the source of truth.

  7. 07

    Validation

    Course structures and content are checked before deployment — IDs, file naming, relationships, step types and Markdown conversion.

  8. 08

    Course analytics

    Author-facing sales and earnings analytics per course, with a separate local cache.

  9. 09

    Terminal interface

    The interactive terminal workspace is built with React and Ink.
